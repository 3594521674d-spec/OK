## 它是干什么的

AI 短剧/漫剧制作 skill 合集，12 个 skill，和咱们知识库同一种东西，最能对照。流程：原著分析 → 分集剧本 → 视觉设定 → 图片/视频提示词 → 确认后生产 → 剪辑成片 → 审查。样片《让你管账号》EP001，20 镜，成本约 40 元。

12 个 skill：short-drama（总控 + 项目初始化 + 跨阶段路由 + Dashboard）、short-drama-novel-analyze（原著拆解）、short-drama-develop（开发/分集大纲）、short-drama-write（剧本）、short-drama-assets（视觉设定）、short-drama-storyboard（分镜）、short-drama-image-prompts（图片提示词）、short-drama-video-prompts（视频提示词）、short-drama-produce（确认后生产）、short-drama-edit（剪辑）、short-drama-review（审查）、short-drama-breakdown（对标拆解）。

仓库 AGENTS.md 的硬规则值得记：skill 自包含（改一个 skill 只改它自己的目录）；知识与做法优先写进 SKILL.md 或 references，脚本只做确定性工作；**规则四级分级**（structural_invariant / reviewed_invariant / craft_default / taste_option）；所有权与审查分离（每个产物只有一个负责 skill，修订不能冒充审查结论，自检要如实标注）。

## 编导环节具体怎么写

来源文件：各 skill 的 SKILL.md、`skills/short-drama/references/creator-documents.md`、`skills/short-drama/references/reference-roles.md`、`skills/short-drama-assets/references/continuity-and-locks.md`、`skills/short-drama-storyboard/references/shot-craft.md`、`skills/short-drama-storyboard/references/keyframe-craft.md`。

### 五份 Markdown 管创作决定（creator-documents.md）
- 每集五份文档，各管各的，固定编号互相引用，不另存隐藏索引或哈希副本：`剧本.md`（write）、`视觉设定.md`（assets）、`分镜.md`（storyboard）、`图片提示词.md`（image-prompts）、`视频提示词.md`（video-prompts）。剪辑时加第六份 `剪辑单.md`。
- `short-drama.json` 管配置：production_profile（制作形态）、rhythm_profile（节奏目标）、creator_authority（创作者已拍板的决定）。**未指定具体模型时直接默认通用档 generic 成稿，不停工追问。**
- 剧本格式：场头 `## EP001-SC001 内 · 地点 · 时间/天气`；对白 `角色（可选表演提示）：台词`；画外音、画外对白、音效、画面文字、连戏说明、转场分别用 `[VO]`、`[OS]`、`[SFX]`、`[画面文字]`、`[连续性]`、`[转场]`。
- 视觉设定格式：开头写明制作形态与时代背景；正文二级标题固定为 `## <人物|造型|地点|道具> · <名称>`；只记跨镜不变的外观特征、本集造型/状态与变化节点。角色声线必填规则：只对剧本里实际有发声对白的人物必填，零台词角色免填；已选定真实样音时写声音参考路径。
- 分镜格式：每镜 `## SHOT-... · 名称`，字段：来源、时长、目的、景别/机位、运镜、起点、动作、终点、图片提示词项、输入参考图、出场设定；`### 首帧提示词` 对应起点定格瞬间，可选补 `### 尾帧提示词` 对应终点。
- 视频提示词格式：每镜一条同编号 `MOTION-...`，字段：分镜、时长、生成方式（图生视频/文生视频）、输入参考图、开场画面、起始帧、动作过程、终点；正文 `### 可复制提示词` 只放 `>` 开头的引用块。
- `creator_markdown_check.py` 自动核对跨文档引用与连戏锁（编号重漏、引用悬空、时长加总、剧本全要素落镜、跨镜连戏状态）。

### 参考图用途十项 + 控制/不得控制（reference-roles.md）
- 每个参考图位写明五项：图位编号与顺序、路径或条目编号与名称、用途、控制、不得控制。
- 用途十项：外貌、主体、造型状态、空间布局、构图、尺度、效果、起始帧、结束帧、风格。每张图只占一个图位，用途填主要项。
- 本集全程不换装的人物：单挂一个“外貌”（或多模态主体参考模式下的“主体”），把本集造型一并写进控制；只有本集内发生换装、淋湿、破损、沾血等变化时，才为变化状态单挂“造型状态”。
- 道具：固定器型、配色与原有旧痕归“外貌”；亮屏熄屏、开合状态或新添污损归“造型状态”。
- REF-… 是项目内真实图片，PLAN-… 是外部工具手动挂图的预留图位；待补参考图不擅自改成文生视频。

### 连戏锁 LOCK（continuity-and-locks.md）
- `- 连戏锁：` 锁死跨多镜反复出现、一旦画偏就会穿帮的静态核心外观（主力制服颜色版型、关键信物主色材质）。全集精选几处关键服装或核心道具即可，不必给每条外观特征都加锁。
- 写法：`LOCK-JIANGCHEN-DRESS《江晨松枝绿常服》（镜头：入画；图片提示词项：IMG-JIANGCHEN-SHEET）· 锁定词：pine-green lapel service jacket`。锁定词是精炼静态名词短语（颜色 + 材质/款式 + 物件），不带句号、动作时态、临时方位或空泛画质词。
- 生效边界：必须原字带入锁定词的位置是静态图片提示词、首帧提示词、未锁住该外观的视频提示词；**已锁外观的图生视频自动豁免**（输入参考图已挂本镜起始帧，或已挂对应设定条目的主体/造型状态参考图时，视频动作提示词聚焦动态表演，不必重复硬塞全身服装描述）。
- 跨场连戏状态只记影响后续接戏的净变化：变化前后状态 + 触发场景 ID 与原因 + 起止有效范围；上集末尾带伤而本集未提痊愈时，默认延续带伤或标待创作者拍板，不凭空复原。

### 分镜方法（shot-craft.md）
- **镜头目的**：写明本镜让观众新看懂了什么或场上谁的处境变了，不拿“中景展示两人说话”敷衍。
- **给足接招反应**：重话砸出、当众拆穿或局势翻盘时，画面要交代受影响一方怎么接住这记重击（单切反应近景、双人同框拍对方僵住后撤，或借全场死寂落定）；同框已演透时不必多切一刀。
- **景别呼吸**：一场戏开场比核心交锋区略放宽半档摆明人物关系，随即落回主力景别（多为中景或中近景），在主力景别上下一档间来回呼吸；大远景与怼脸大特写留给关键重音，用完退回主力景别。
- **对白估时**：4–5 秒镜头通常从容演完 1–2 个连贯动作，硬塞三四个大动作极易抽帧变形；长台词顺着说话人与听者反应拆成两三镜接力演完。
- **对白场切法**：一镜拍完一轮发问或回击，话锋突转处落刀；杀伤力最重的那句台词优先切给听话人看变脸反应；正面对峙守住同一机位侧正反打；砍掉纯水时长的无戏空镜。
- **重头戏拆镜前理清七个支点**：这场戏翻了什么盘、观众代入谁、怎么借房间家具封堵施压、先给反应还是先亮证物、哪几镜稳架不动哪一下推切、场尾定格在哪一帧、环境声在哪一刻骤停留白。
- **只有创作者明确要求比选时才暂停等拍板**：常规拆镜直接一气呵成输出正式分镜，不先给 2–3 套方案等选。
- **首尾成对**：仅当收尾构图非卡准不可且目标模型支持垫尾帧时，才补写尾帧提示词；同场连续戏且模型支持视频续接时，优先用上一镜成片尾端续接。

### 首尾帧写法（keyframe-craft.md）
- 五步编写顺序：画幅取景与焦段透视 → 空间层次与陈设尺度 → 人物落位与身体朝向（**胸口身体朝向与转头方向分开写清**）→ 定格神态与肢体细节 → 实景光线、画风与排除项。
- **同机位切景或微调优先基于上一镜首帧派生**：相邻镜头同一机位朝向时，直接拿已确认的上一镜首帧配合改图模型派生下一镜首帧，最大限度锁死人物脸型、衣褶与背景陈设连戏。
- 反打翻面或大换背景朝向时改挂场景图（用途：空间布局）配角色设定图（用途：外貌），不再拿上一镜反面首帧硬改背景。
- 单帧定格防串戏：首帧只画起点已到位的姿态与物件状态，绝不提前画入半途或终点才发生的结果；尾帧删净开场已消失的旧姿态；先后顺序的过程词、神情渐变、推拉摇移运镜一律留给视频提示词。
- 光源来向与受光面连起来写：主光从画面哪一侧打来、亮哪半边脸、暗部保不保留眼神光；角色设定图用中性平柔光，进场入镜后按房间真实光源方向落笔。

### 视频提示词（video-prompts）
- 动笔前按分镜的输入参考图区分路径：图生视频承接分镜参考项；文生视频填非空开场画面；参考图待补时先自动查找可用真实图片，仍有缺口就转成 PLAN 挂图计划照常完成，不擅自改成文生视频。
- **参考分工与连戏锁**：已被起始帧或设定条目参考图锁住外观的对象，专注描写动作与神态演变，不重复堆砌已知静态外观，也不重复粘贴静态锁定词。
- **声音分流与台词守真**：后期配音路线专注画面口型与呼吸神态；音画同出路线写清声源、说话人、语种、单次逐字台词与环境底声。严禁编造剧本、视觉设定与分镜未声明的人物发声台词。
- 组织动作、运镜与声音正文：起手姿态 → 核心动作（触发、方向、接触参照物、落点）→ 微表情与反应层次 → 运镜与焦段 → 声音与终点状态；需要精确卡切点时用互不重叠的标秒时段铺满本镜时长。
- 跨镜硬切接同一连续动作需像素级咬合，或创作者明确指定视频向后延长时，才用上一段真实成片或 ffmpeg 抽真实末帧续接；相邻镜头默认各自按已定稿首帧独立生成，不默认锁死为“待续接、不可提交”。

### 确认后生产（produce）
- **预览后确认才执行**：先汇总预览整批清单（总条数、目标接口/模型、时长或尺寸参数、全部输出路径），等创作者亲眼看到预览清单后明确回复确认，再写入确认回执。笼统的“继续”“预算够用”、上游已定稿或旧确认码均不算本次确认，严禁代填。
- 对应条目段落、参考文件、参数或输出路径一旦改动，原确认码自动失效。
- 断点续跑自动跳过当前指纹下已成功且本地产物完好的条目；中途断网或轮询中断时先查 orphaned_provider_job（孤儿远端任务），用 collect 直接取回原远端任务结果，**不重复扣费**，也不消耗新确认码；仅当远端任务确已失败且无法取回时，才重新确认重跑。
- 生成接口配置存放在项目目录之外，API 密钥只从环境变量或系统凭据库读取，项目文件夹与创作台界面不保存任何密钥。
- 批量生产按单集建批次，避免把整季几十集塞进同一个确认包；额度有限时按集拆批，一集的镜头全部跑完再建下一集，避免按资产类别横铺多集导致额度中途用完时手里没有能剪的整集。

### 剪辑（edit）
- 剪辑单每段 `## CUT-...`，绑定一个来源编号和一个真实媒体文件；字段：来源、入点、出点、时长（保留两位小数，出点 − 入点 = 时长）、**取舍（入点理由；出点理由，写清入出点那一帧的具体画面动作与切镜理由，不写空泛的“节奏需要”）**、声音、画面、字幕（逐字照抄剧本台词与标点）、画面文字、音效、运镜（仅静帧段）、配音、环境声。
- 工作流：标定可用区间（从头到尾播放每条素材，记下可用起止秒数及区间外的毛病：开头呆立、结尾走样、画面发白、动作回弹、重复动作）→ 定位台词起止与入出点 → 排定镜序与接镜调色 → 处理声音字幕 → 保存渲染看片验收。
- 开头写交付规格：成片目标时长、画幅与帧率、交付响度、字幕；全集交付时未剪进成片的镜头写清单加理由（文件缺失｜质量不可用｜叙事取舍）。
- 不反向篡改上游定稿文档：剪辑可裁短、删减、调序，不回写篡改上游定稿，也不擅自加塞无剧本依据的台词。

### 审查（review）
- 只出具审查问题单、结论和修改要求，不直接改原稿。优先由未参与本轮执笔的独立审稿人执行；执笔人自检时如实标明自检。
- 问题单格式：`## <Blocker|Major|Minor|Note> · REV-<编号> · <标题>`，标题下逐行写位置、证据、影响、修改要求、规则。
- 严重程度四档：Blocker（阻断交付的不变量结构错误、核心事实穿帮、泄密违规或不可挽回的成片缺漏）、Major（违背 structural_invariant 或 reviewed_invariant、伤及剧情因果理解、跨镜连戏或成片主体与台词完整度的中度硬伤）、Minor（craft_default 范围内的套路重复改进建议、局部瑕疵提醒或裁切/后期可修项）、Note（审美与风格参考建议）。
- **规则等级与严重程度上限**：craft_default 偏离仅可记为 minor 或 note，绝不升格为 major，也绝不单凭 craft_default 触发 REVISE；taste_option 一律仅记作 note。
- 结论：APPROVE（无 Blocker，且无未获创作者显式豁免的 Major）、APPROVE_WITH_NOTES、PROVISIONAL（无 Blocker，仅剩不影响核心主线推进且已写明下阶段修正方案的局部问题）、REVISE（存在 Blocker 或未获豁免的 Major）。
- 局部补丁与亮点保护：返修意见只针对病灶开最小局部补丁，不借局部毛病要求整集推倒重写；对比新旧稿时若发现润色压稿误删了抓人钩子、高潮金句或精妙包袱，单列“被删的强钩子”记下原位置与原句。

### 对标拆解（breakdown）
- 只读取当前对话提供或明确授权的素材；原片、转写稿、还原结果一律放在对标目录，不进入正式交付或公开文件；学习用途的对标剧真实剧名、专有角色名、逐字台词与独有桥段严禁进入原创项目文档。
- 测量：抽取样本集，用 measure 生成代表帧缩略图拼版并挂接字幕转写拆解全局，仅对重点集或高光段落按需跑 shots 逐镜切片。
- 看片细读维度：整剧集长编排、开场第一拍、信息交代方式、对白密度、镜头分切、集尾留钩与跨集衔接、画幅与制作形态；每一项分开写实测与画面事实、作用分析、待确认盲区。
- 同尺对照：用同一把尺子把本项目计划或自家成片和对标剧并排拉差距表，区分建议补强的差距与疑似有意取舍的设计。

### 原著拆解与开发（novel-analyze + develop）
- 原著拆解：章节索引 → 改编价值快评（抽样）→ 逐章情节提取（每章拆进 ch-N-extract.md）→ 剧情单元与爽点梳理 → 人物合并与设定跨卷演进 → 改编取舍与分集候选。只拆合法持有的作品，不改原文、不整段照抄原句，只记章节位置、起止行号和剧情作用概括。
- 开发：轻量单集可直接在 creative-brief.md 写合一简纲，不强制拆 story-engine 与 episode-map；已有明确设定直接顺着深挖，不强行凑 2–3 个备选方向等拍板；只有模糊点子时才给两三个打法真正不同的备选方向。
- 分集大纲 episode-map.jsonl 是多集连载按需分集状态账，每集只记本集核心推进与单向交接给下一集的 handoff_state，不重复抄写上一集状态。
- 常规连载集在抛出集尾悬念前宜先落定一个本集阶段结果；单元温情剧也可在情绪落点舒缓收束。

## 咱们缺什么

1. **五份文档 + 自动核对**：咱们是一份主稿 + 资产卡 + SHOT 表，没有五份文档各管各的的分工，也没有自动核对脚本。《伞》台词全空的事故就是缺这一道。
2. **参考图用途十项**：咱们的 REF 槽位只有顺序，没有用途和控制/不得控制声明。
3. **连戏锁 LOCK + 豁免规则**：咱们有锚点，但没有锁编号、锁定词和“已挂起始帧就豁免贴锁词”的规则。
4. **审查分级与问题单格式**：咱们的质检六闸没有 Blocker/Major/Minor/Note 分级，没有结论四档，没有“只开局部补丁”的明文。
5. **剪辑单**：咱们没有剪辑环节文档，豆包出片后怎么拼、入出点怎么取，全凭手感。
6. **确认后生产的工作流**：咱们是小pa直接出图出提示词、用户当场验，没有“预览清单 → 明确确认 → 确认码 → 执行 → 断点续跑 → 孤儿任务取回”的成套做法；其中“改动即确认码失效”和“孤儿任务取回不重复扣费”两条值得学。
7. **对标拆解同尺测量**：咱们的老布拆解是逐条文本拆解，没有镜长、对白密度、开场第一拍这些量化测量。
8. **规则四级分级**：咱们的规则没有分 structural_invariant / reviewed_invariant / craft_default / taste_option 四级，分不清哪条是硬红线、哪条只是手艺建议。
