## 经验卡机制（本 skill 的进化层）

**触发**：每次交付后用户给了负面反馈、或自己发现翻车，必须当场记卡。不复盘不记 = 白翻车。

### 经验卡格式（一条一卡）

```
【经验卡 EC-NNN】日期：
- 现象：用户看到了什么问题（引用原话最好）
- 根因：流程哪一环漏了/错了（指向具体锁或阶段）
- 修法：以后遇到同类怎么做（写成可执行判据，不写态度）
- 判据：能不能机检？能→建议加进哪个环节的检查清单
- 状态：待观察 / 已验证 / 已晋级
```

### 晋级规则

- 同类现象累计 **3 张卡** → 升级为规则，写进对应 references 文件（改模板/闸门/清单），台账标记「已晋级 + 落点」。
- 单张卡但根因是「硬门缺失」（比如锁没锁就动笔）→ 直升为规则。
- 规则进正文前先跑一次小规模验证，别让一张卡污染主流程。

### 台账位置与边界

- 文件：技能目录 `_内部_经验台账.md`（内部档案，不进交付）。
- 编号从 EC-001 连续递增，不复用、不删卡（写废的标「作废」留痕）。
- 台账只记「流程与判据」类经验，不记项目剧情内容。

### 本包从四家源仓库直接继承的已验证经验（预置卡，从根上就执行）

- **EC-001** 输出超过约 8k 字后模型必然开始「同上/其余同理」敷衍 → 根因：单批超预算 → 修法：主动按结构切批，一场戏不劈两半 → 已晋级，落 SKILL.md §一。
- **EC-002** 参考图拿「看起来的风格词」手搓，而不是回风格库取正主槽位 → 画风崩 → 修法：风格词只能来自定调卡/画风锁，选卡必须弹给用户勾 → 已晋级，落 SKILL.md §二 F 锁。
- **EC-003** 「图不在 skill 手里」却把出图当前置阻塞 → 执行者卡死或假装通过 → 修法：M0/M1/M2 三形态 + 不索图不阻塞 → 已晋级，落 SKILL.md §三。
- **EC-004** 派生图参考派生图 → 一致性连锁崩 → 修法：单根锚点体系，派生只认根图 → 已晋级，落 references/04。
- **EC-005** 机检全绿被当任务完成，但该交的产物没交 → 修法：交付前逐项核对产物清单（锁/形态/卡数/镜数/闸门结论/台词对照）→ 已晋级，落 SKILL.md §五交付自检行。
- **EC-006** 用户随口提剧名被当原创处理 → 做出来的东西方向全错 → 修法：提到剧名默认按对标锁询问 → 已晋级，落 SKILL.md §二 〇锁。
- **EC-007** 多段任务段缝不锁，成片每段零记忆跳切 → 修法：立项期判多段并锁 D 四选一 → 已晋级，落 SKILL.md §二 D 锁。
- **EC-008** 台词在投喂层被静默精简丢失 → 修法：台词完整性对照 + 分镜层无删词权 → 已晋级，落 SKILL.md §五。
