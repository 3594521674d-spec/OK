# 漫剧融合 Skill（manju-fusion）

一句话定位：用户说一句话，剩下全自动——从点子到可直接投喂视频模型的完整稿件，中间只在「锁」和「阶段门」停下来确认。

融合来源：zenstory-ai/drama-skills（数据契约与工序）+ manju-laoli-skill（锁系统/打戏/投喂质检）+ shuohao-skills（锚点图一致性/站位）+ ai-manju-skills（21 题材配置与用户界面）。参考层在 `references/`，本文件是唯一总控。

## 一、总流程（五阶段）

```
一句话需求
  → 〇 锁定期（素材来源/模型/画幅/题材等，见二）
  → ① 立项：企划案（13 项框架，题材配置填差异槽位）
  → ② 剧本：分集剧本（改编则先过改编分析）
  → ③ 资产：P/D/S/FX 卡 + 生图提示词（锚点图体系）
  → ④ 分镜：SHOT 表 + 视频提示词（模型方言层）
  → ⑤ 质检 + 发布包：QC 清单、投喂稿、封面/文案/合规
```

- 每阶段产出落盘为 md（chat 工具型环境写文件；纯聊天窗则分批输出、用户说「继续」推进）。
- 阶段门：①→②、②→③、③→④ 之间各停一次向用户确认核心设定（人物表/空间表/画风），过了不再回头重复追问。
- 单批输出预算：一批 ≤8000 字，接近上限主动切批，按「集 > 场 > 段」结构切，一场戏不劈两半。禁止「同上/其余同理/省略」凑数——数量不够就是没交付。

## 二、锁系统（动笔前必须锁完）

任何一道未指定 = 停下询问并摆出选项让用户勾，禁止默认跳过。用户明确说「你定/按推荐来」才算答复。

| 锁 | 内容 | 说明 |
|---|---|---|
| 〇 素材来源 | ① 原创 / ② 改编（有原著）/ ③ 对标爆款 / ④ 热点速成 | 提到剧名 = 大概率想对标，别当原创处理。③④ 先出《对标情报卡》（见 references/05） |
| A 模型 | Seedance 2.5 / 2.0 / MiniMax H3 / 即梦-通用 / Wan | 锁定后语法全按该方言执行，禁止混写，方言见 references/02 |
| B 画幅 | 16:9 / 9:16 / 21:9 | 资产板画布固定 16:9 不随成片变 |
| C 交付形态 | ① 只要稿件文档 / ② 只要分批聊天输出 / ③ 都要 | |
| D 段缝衔接 | 多段任务（目标时长÷单段上限>1）必锁四选一：① 末帧定格承接（尾帧锚定）② 换机位硬切 ③ 空镜过渡 ④ 技巧转场 | 立项期判死，不许推到分镜阶段 |
| E 题材 | 21 题材之一或自定义 | 直接挂 references/01 对应题材配置 |
| F 画风 | 推荐候选卡让用户勾（必含「按你的推荐走」） | 选定即冻结，换风格=重开任务 |

锁完写入《立项基准表》，全流程不再更改；用户中途改锁 = 该阶段产物重跑并明说影响范围。

## 三、素材形态（M 轴，与锁正交）

承认现实：图由用户拿提示词去外部平台自己跑，图不回传。三档：
- **M0 纯提示词**：只给提示词，不编号。
- **M1 编号占位（默认）**：资产给编号（P01/D01/S01…），《素材接线单》登记「图号→提示词→建议参考方式」，用户出图后自行回填路径。
- **M2 已入库**：用户回传了图，可作参考图引用。

四铁律：不索要图片、不因缺图阻塞、不写不存在的图号、每次交付首行声明形态。参考图引用语法统一用槽位三段式：`REF-<槽位>（顺序）·《名》（用途；控制什么；不得控制什么）`——例：`REF-主角形象（1）·P01三视图（锁定人物形象与服装；不得控制构图与姿势）`。

## 四、各阶段规程

### ① 立项 · 企划案（13 项，分 4 批出）

通用 10 项：卖点一句话 / 梗概 / 人物表 / 篇章结构 / 逐集钩子表 / 商业节奏（爽点间隔 ≤3 集）/ 伏笔账 / 视觉总纲 / 声音总纲 / 制作与发布。
题材差异 3 项由 `references/01` 题材配置填：题材规则表 / 逐集进度表（复仇表/线索表等）/ 空间清单。
默认集数与时长按题材主流（红果漫剧 1.5–2.5 分钟/集；除非题材配置另有说明）。

### ② 剧本

格式：场 / △动作 / 台词 / 内心（注明「OS·闭口」，不写具体口型台词）/ 画外 / 结尾钩子 / 本集进度行 / 对白字数行。
对白门：每集 300–500 字对白，开口时长占全集约 2/3；单句 ≤35 字；台词时长按 4 字/秒估。
改编（素材来源②）前置五步：章节索引 → 改编价值快评（停，问用户）→ 逐章功能提取 → 剧情单元与爽点聚合 → 人物归并 + 改编价值判定，产出候选集清单，每条带原文 locator 可回溯。
对标（③④）前置：出《对标情报卡》十三字段（含可迁移点/不可迁移点两栏，只填热度不填迁移点=白采）+ 信源分级（T1官方/T1.5实测/T2讨论，T2 不当事实用）。

### ③ 资产

卡型体系（模板细节在 references/04）：
- **P 人物卡**：三视图（正侧背同排等距）、表情四态、服装卡、状态卡（标注使用集数）、一致性锚点 3–4 个不变特征；悬疑等题材可加背影卡（未揭身份人物）。
- **D 道具卡**：四格板，正反面逻辑。
- **S 场景卡**：母版 + 九宫格 8 字段。
- **FX 特效卡**：按题材配置。
- **STYLE 定调图**：题材有双色调需求的出两张（如今生/前世）。

一致性铁律（shuohao 锚点图体系）：每个角色一组图只有一个「根」（三视图或锚点卡），所有派生图（表情/服装/状态）只允许参考根图，禁止派生参考派生——防连锁崩。人物提示词带固定负面词表（见 references/04）。角色板图面零文字。

### ④ 分镜

SHOT 字段并集（模板在 references/04）：镜号 / 职责（这场戏为什么有这镜）/ 来源场次 / 时长 / 景别 / 机位与焦段 / 运镜（固定也要写理由）/ 起点 → 唯一动作 → 终点 / 声音与台词估时 / 站位与朝向 / 视线落点 / 首帧参考 / 段缝衔接方式。
关键帧提示词：冻结起点状态，删除「终点才有的信息」（防止模型抢跑）。
打戏自动判档：R1 真人格斗 / R2 武侠 / R3 玄幻法术，规则在 references/03。
机位基调：侧 45° 为默认，常规平视 ≤30%，荷兰角每集 ≤1。切镜必须带来信息/权力/情绪/空间/节奏五变化之一，否则不切。

### ⑤ 质检 + 发布

投喂稿组装前六道闸（默认全跑，逐条给结论）：
1. 节奏：爽点/钩子间隔；
2. 台词时长：逐镜台词字数÷4字/秒 vs 镜时长；
3. 字数：单段投喂稿 Seedance 2.5 ≤3600 字 / 2.0 ≤2900 字（其他方言按 references/02）；
4. 可投喂语义：工程术语、内部 ID、meta 语言清出正文；
5. 参考图数量：不超过该方言上限（2.5 全能参考 30 图）；
6. 编号与素材形态一致性：稿件图号必须能在素材接线单找到，M1 形态下不声称已核验。

台词完整性对照：剧本层每句台词必须能在投喂稿里找到（防静默丢句）；分镜层无权删台词，只能给「精简建议清单」。

通用连续性自查 15 条 + 题材追加项（references/01）；连续性台账（人物账/场景账/时间轴账）跨集维护。

发布包（最后一批交付）：封面（3:4 与 4:3 各一）、片尾卡、8–10 秒预告脚本、标题×3（钩子式）+ 简介 + 话题标签 + 置顶评论、AI 生成内容合规标注。

## 五、交付纪律

- 一次任务对外最多 3 件：主稿件 md + 投喂稿（可并入主稿）+ 预演故事板（可选）。中间工作文件（IP 圣经、分集规划、质检报告）是内部档案，文件名前缀 `_内部_`，不进交付。
- 主稿正文只放两样：资产提示词 + 分镜提示词。出现 P/D/S 图号就必须同稿带资产段（或主稿写明「资产另册：{文件名}」）。
- 命名全中文：「第01集」；技术标识（Seedance 2.5 / 9:16 / M1 / P01）保留原文。
- 交付前自检一句话汇报：「锁：A=2.5 B=9:16 E=悬疑 · 形态 M1 · 资产 12 卡 · 分镜 28 镜 · 闸门 6/6 过 · 台词对照 0 丢句」——有 FAIL 项必须明说，禁止拿「整体没问题」糊弄。

## 七、经验回写

每次交付后（用户主动或踩坑后）：把翻车/修正记成经验卡（现象→根因→修法→判据），落入 `_内部_经验台账.md`；同类卡累计 3 次即晋级为规则，写进对应 references 文件并在台账标记「已晋级」。这是本 skill 的进化机制。

- 「做一集/一季 {题材}」→ 锁系统弹卡 → 全流程
- 「这场打戏出分镜」→ 判档 R1/R2/R3 → references/03
- 「对标《X》」→ 情报卡 → 用户确认 → 进剧本链
- 「继续」→ 推进下一批
- 「改：{内容}」→ 局部重跑受影响产物，不重放全流程
